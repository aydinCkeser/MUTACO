# Documentation authority

| Question | Authority |
| --- | --- |
| Which algorithm, coordinate convention or policy applies? | The [scientific contracts](../scientific_contracts/README.md) and [scientific registry](../scientific_contracts/scientific_registry.toml) identify each version and status. Data-defined profiles select registered options. |
| Which comparisons support a manuscript claim? | Read the [paper scope](../scientific_contracts/paper_scope/README.md), the [experiment registry](../results/experiment_registry.toml), and the corresponding versioned result manifest together. |
| Has a Paper Lab bundle been independently promoted? | The [promotion bindings](../results/paper/promotion_state.toml) preserve the reviewed source-path and bundle-identity pairs used alongside the experiment registry and a reproduced report. |
| Where is the implementation work recorded? | The [migration map](decisions/repository_migration_map.md) records the physical paths, compatibility addresses, exceptions and actual validation scope. |
| What did an older checkpoint say? | The [archived state, schema and coordination records](../scientific_archive/project_records/README.md) and [dated strategy and status notes](history/README.md) retain the evidence applicable at their own revisions. |

[Software terms](../LICENSE), [dataset terms](../DATA_LICENSE.md), and [data availability](../DATA_AVAILABILITY.md) define the release scope. Historical authorization fields apply to the operations recorded there.
