# Analytic target-matching experiments

The [forward models](forward_models/README.md) define known parameter-to-response maps. The [experiment configurations](configs/README.md) specify hidden targets, budgets, noise and comparison methods. The [installation guide](../../infrastructure/local/README.md) describes the independent `mutaco_analytic` distribution.

These are readable scientific experiments, not unit tests and not core MUTACO
implementation. Each entry point follows the same visible protocol:

1. load declared scientific settings;
2. resolve CUDA or the reported CPU fallback;
3. construct a target response from a hidden `theta_star`;
4. give MUTACO the target response, but not `theta_star`;
5. run sequential target matching with visible progress;
6. report `theta_recommended`, response matching, errors, branches, and timings;
7. repeat the scientific run and verify deterministic replay;
8. write JSON evidence and SVG plots.

The hidden parameter remains visible to the human reader in configuration and
result provenance. It is withheld from MUTACO, so these are transparent
acceptance experiments rather than blinded benchmarks.

## Running from PyCharm

Open any `run_*.py` entry point and press **Run**. No arguments are required.
The script detects direct-file execution and resolves its default
configuration and output directory from the repository location, independently
of PyCharm's working directory.

Use the pinned `mutaco-sbi` environment for paper, SBI and pytest workflows. The explicitly gated `mutaco-dev` launcher supports non-SBI experiments. The
handwritten entry point writes by default to
`runs/analytic_target_matching/handwritten/`.

## Handwritten two-parameter experiment

```powershell
python -m experiments.analytic_target_matching.run_handwritten `
  --config experiments/analytic_target_matching/configs/handwritten.json `
  --output runs/analytic_target_matching/handwritten `
  --device auto
```

This uses the documented handwritten `P=2`, `M=3` Torch simulator.

## Frozen-GP six-parameter experiment

```powershell
python -m experiments.analytic_target_matching.run_gp_landscape `
  --config experiments/analytic_target_matching/configs/gp_landscape.json `
  --output runs/analytic_target_matching/gp_landscape `
  --device auto
```

This checks that the same simulator-independent MUTACO workflow supports a
deterministic `P=6`, `M=4` forward.

## Complete acceptance suite

```powershell
python -m experiments.analytic_target_matching.run_suite `
  --output runs/analytic_target_matching/suite `
  --device auto
```

The suite runs both configurations under identical runner settings. It
preserves **Prompt 5** as the milestone that introduced and accepted this
vertical slice. The former
`python -m experiments.analytic.prompt5_acceptance` command remains available
as a compatibility entry point.

Use `--device cuda` for strict later CUDA execution without changing the
scientific configurations.

## Noisy hidden-target cohort (Prompt 5A)

```powershell
python -m experiments.analytic_target_matching.noisy_cohort.run `
  --config experiments/analytic_target_matching/configs/noisy_cohort_100.json `
  --output runs/analytic_target_matching/noisy_cohort_100 `
  --device auto
```

This runs independent MUTACO inversions over a predeclared scrambled-Sobol
bank of hidden `theta_star` values. Each target has separately derived target
noise, inference, and fresh held-out-assessment seeds. The default cohort has
100 targets; edit `campaign.target_count` in a copied configuration to change
its size. With otherwise identical target-bank settings, smaller cohorts are
exact prefixes of the default bank.

The output contains:

- `target_bank.json`, complete per-target result/history/assessment artifacts,
  and SHA-256 sidecars;
- `metrics.json`, `metrics.csv`, and `summary.json`;
- first/middle/last deterministic replay evidence;
- visible progress and ETA in the console and `progress.jsonl`;
- primary target-response L1/L2 and design-space L2 distributions;
- noiseless latent-response diagnostics;
- precomputed box statistics and paired PDF/SVG plots.

Plotting is separate from inference. Recreate plots from stored results with:

```powershell
python -m experiments.analytic_target_matching.noisy_cohort.plot `
  --input runs/analytic_target_matching/noisy_cohort_100 `
  --style experiments/analytic_target_matching/noisy_cohort/styles/noisy_cohort_default.mplstyle `
  --formats pdf svg
```

The plotting style and formats can be changed later without rerunning the
cohort. PDF and SVG are both generated by default.
